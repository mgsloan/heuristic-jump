## Hypothesis

The `found:` clause is the shape the last campaign named as the default false
blocker: "driver holds no document map, and `DidChangeTextDocumentParams` and
`DidSaveTextDocumentParams` have no reader". Delete the missing-subsystem
clause — there is no actor and no transport — and what remains is an ordinary
owned data structure: a `FxHashMap<DocumentUri, Open>` whose rows are trusted
or not, four methods that read the four state-bearing notifications, and the
three O(1) self-checks §8.6 names. None of it needs a channel, and all of it
tests without one, exactly as `TreeCache` and `PendingQueries` already do.

The claim's second half — "queries against an untrusted document abstain
unconditionally" — is the part worth making mechanical rather than asserting.
The strongest available form is that an untrusted document *cannot produce the
input a query needs*: distrust drops the rope, `Documents::query` hands back a
`Trusted` only for a row that still has one, and `OpenDocument::new` (the only
route to a `SnapshotSeed`, which is the only route to `dispatch`) takes a
`Trusted` and has no other constructor. Then "abstain unconditionally" is not
a rule anybody follows; it is the absence of a way to do anything else.

`deps.md` §10's ninth arm arrives with this: `Document(DocumentError)` is
listed there as "didChange for unopened doc, bad range, ...", and
`error.rs`'s module doc already says it "arrives with its producer".
