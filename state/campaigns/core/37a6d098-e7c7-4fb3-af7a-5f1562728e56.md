## Hypothesis

The sweep itself is **done** — `cargo test -p rope` is green at 24 upstream
tests plus 5 of ours, and `tests/newtype_api.rs` already scans every `pub fn`
for a bare primitive. So these sections are unjudged rather than gapped, and
what they lack is not implementation but **mechanism**: the existing scan holds
only the *negative* half of §4 (no bare `usize` in a signature, no trait impl
against a bare integer). Every *positive* claim — that the operator table is
exactly the rows §4 prints, that `Offset + Offset` is absent, that the four
line-shaped newtypes have no arithmetic at all, that `TextSummary`'s fields are
typed, that the four char-unit functions got `CharCount` and `Utf16Column`
rather than being left bare, that `Display` prints the bare number so `Point`'s
`Debug` keeps its output — is currently held by nothing but reading.

Expectation: the sections go clean on mechanism, plus a small number of Class A
document repairs where the document describes the pre-sweep world.

## Experiments

### E1 — the nine/eight split, and the comments that describe the old world

§7 and `vendor/README.md` both say `#[gpui::test(iterations = N)]` was on
**nine** functions. There are eight `seeded` call sites. Fetched upstream at
the pinned revision `90d024b8`: there are nine `#[gpui::test]` attributes, of
which **eight carry `iterations = N` and one is bare**
(`test_point_utf16_to_offset_clips_to_correct_absolute_offset`,
`chunk.rs:1235`). All nine survived — the bare one is a plain `#[test]` at
`vendor/rope/src/chunk.rs:1332`, needing no `seeded` and one changed line
rather than two. So "every test is preserved" holds and the *count* is what is
wrong. Class A.

Alongside it, two code comments that were true before the sweep and are not now
(the audit carries both as minors on §2): `offset.rs`'s "Nothing in rope uses
these types yet" and `point.rs`'s "this file's own `row: u32` is still bare".

### E2 — the operator table, as an inventory rather than a prohibition

§4 prints the rows the byte pair gets and one row that must **not** exist
(`Offset + Offset`), and says the four line-shaped newtypes get none at all.
Nothing holds any of it: the bodies compile either way, and the existing scan
only rejects impls that name a bare integer. A scan comparing the operator
impls against the table in both directions — a missing row and an extra row
both failing — with a negative control.

### E3 — the typed surface, held by the compiler

`TextSummary`'s fields, the four char-unit functions §4 says get the *correct*
newtype rather than being left bare, `Point::new`/`PointUtf16::new` taking
newtypes, `slice_rows`/`line_len`, `Rope::len -> ByteLen`, and the
`ZERO`/`MAX`/`Display` triple every newtype is required to have. All of it is
compile-time, so it belongs in a test as bindings with written-out types.

### E4 — §7's kept tests, as a count that cannot drift

The nine/eight discrepancy in E1 existed because nothing counted. A test
asserting the `seeded` sites against the `_inner` bodies, that no `gpui`,
`zlog` or `ctor` reference survives in either vendored crate, and that the
ninth conversion is a plain `#[test]`.
