## Hypothesis

The first three say the same thing from three sides: `realise` is "called by
the worker, never by `core`"; "the parse is paid inside the worker … `core`
builds seeds and never realises one"; "the conversion happens in the worker,
not in `core`, because it **reads the target file**". All three were false for
one reason — `Actor::requested` called `dispatch` in line — so they close
together or not at all, in `actor.rs` + `dispatch.rs`.

It is not an aspiration in a document. `actor.rs` already refused the `didSave`
checksum read because "reading the file on this thread is the one thing
`shim.md` §2 forbids `core` outright", while the query path beside it did a read
per returned location on that same thread. The code contradicted itself and
§8.4 is the sentence that says which half is wrong — so the code moves, not the
spec.

`deps.md#10` was assigned as a rider and is **stale**: `a67cd3f` closed it eight
minutes after the audit that opened it, and gap-log rows 15 and 16 never
re-judged the section. It stopped being free anyway — moving the conversion to
a pool thread moves `classify`'s log line with it, and `tracing`'s default
subscriber is thread-local first, so "explicit and logged" needed work to
*stay* true.
