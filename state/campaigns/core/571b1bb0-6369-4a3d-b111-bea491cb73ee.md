## Target

`core.md#4-project-file-enumeration`, all three of its gaps:

- `bc6f2ede8e` — the driver caches a file list, built lazily on first need and
  refreshed in the background.
- `ccf81307a8` — `AbstainReason::NoCandidates` specifically triggers a
  debounced background rescan, while the triggering query still abstains.
- `8390d79ba0` — in proxy mode the editor's watcher notifications are teed to
  `core` and set a stale flag with O(1) work, never reading the payload.

They are one piece of work seen from three sides: the three claims are the
*owner* of the file list and its two invalidation triggers, which §4 says
share one debounce rather than one each. Neither trigger can be written
without the owner, and the owner is pointless without them. Closing all three
is what makes the section clean, which is the only thing the number counts.

## Hypothesis

The gaps' stated blocker — "an owner that does not exist" — is not one. What
is missing is a struct in `driver` holding the `Arc<FileList>`, a named
background thread that walks, and a debounce; `shim.md`'s actor loop is *not*
needed for any of that, exactly as `TreeCache` did not need it (`core.md` §2
was judged clean with `Parsed` travelling by return value).

The two triggers reduce to O(1) state transitions on the same field, so "the
two triggers share one debounce" becomes a property of there being one field,
and "never reads the payload" a property of the tee taking no payload
argument at all.

## Outcome

Confirmed. `core.md#4-project-file-enumeration`'s three gaps are closed.

What the audit called a blocker was, again, not one: none of the three claims
needed `shim.md`'s actor loop, its transport or its codec. The owner is a plain
struct with `&mut self` methods, the background half is one named thread, and
both invalidation triggers are O(1) transitions on a single `Refresh` field —
which is what makes "the two triggers share one debounce rather than one each"
true by construction rather than by discipline.

Three claims were made mechanical rather than asserted:

- *never reads the payload* — `watched_files_changed()` takes no argument, so
  there is nothing to read.
- *`NoCandidates` specifically* — `AbstainReason::file_list_evidence` is an
  exhaustive match in `shared` (the enum is `#[non_exhaustive]`, so the same
  match in `driver` would need the wildcard arm `CLAUDE.md` bans), and a new
  variant fails to compile until it is classified.
- *neither blocks a query* — `list()` returns the held `Arc` whatever the
  refresh state is, asserted mid-flight.

Left for a later campaign: nothing in §4. The cache has no *production* caller
— `run` is still a config report and there is no actor loop — which is the same
state `TreeCache` is in and is `#both-sides-are-sets`' gap, not this one's.
Experiment 2 put it on the tested query path instead, which is the closest a
real caller gets before the loop exists.
