## What the reading turned up before any edit

**The `add_newline` line is upstream's, verbatim.** Fetched
`raw.githubusercontent.com/zed-industries/zed/90d024b8.../crates/rope/src/rope.rs`
— upstream reads `self.len_utf16 += OffsetUtf16(self.len_utf16.0 + 1);` at its
line 1330. So the conversion did *not* change arithmetic and §3's contract
held. What is true is that the method is wrong, is public, and has no caller in
either copy. Upstream also omits `self.chars += 1` while
`TextSummary::newline()` twelve lines above sets `chars: 1`, so the method
disagrees with both `newline()` and `From<&str>`.

That makes this an upstream bug fixed deliberately, recorded as its own patch
class rather than as a conversion edit — otherwise the next re-sync reads it as
sweep fallout.
