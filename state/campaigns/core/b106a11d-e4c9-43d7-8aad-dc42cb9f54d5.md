## Hypothesis

§4 prints `chars: CharCount, // usize before and after`. §2 spends a paragraph
on why: `CharCount` is "the one member of the family backed by `usize` rather
than `u32` … the width of the widest thing it has to hold rather than a
preference", because `TextSummary.chars` accumulates across the whole rope, and
a `u32` "would have silently capped a summary at 4G scalar values — which is an
edit to the *arithmetic*, exactly what §3 says a hunk may never be".

The code has `CharCount(pub u32)`, and `vendor/README.md` records the narrowing
as deliberate: "which is what §4's printed struct asks for and which bounds a
summary to 4G scalar values — the bound `Point.row` already imposed."

**Both halves of that justification are false**, and the second is false
against a sentence §2 wrote to pre-empt it: "The bound `Point.row` happens to
impose is not an argument for imposing another." So the design is internally
consistent and the code took the losing side. The direction is not a judgement
call: `b506a5b` defined the newtypes on 2026-08-02, and `1b9dd51` — *Michael
Sloan, "Design change: CharCount is usize"* — moved the document on 2026-08-04.
The code simply never followed a human design change. **The code moves; the
design is not touched.**
