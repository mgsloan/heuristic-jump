## Hypothesis

The conversion is ordinary code that has been blocked on nothing: every piece
it needs already exists (`WirePosition::encode`, `ProjectView::read`,
`Location::{uri,range}`), and the reason it was never written is that
`dispatch` had no encoding parameter and nobody had a reason to add one.

What the section says makes it free — "at the moment the handler returns,
every target file's text is already in the view's cache" — is the one thing
that is *not* true today: `conformance-005` ruled out the per-query read
cache, so each target file is a fresh disk read. Expected to be a comment
rather than a blocker; adding a cache here is what that ruling forbids.

Expected to surface: `56ccb86901` is Class A, and the honest resolution is to
narrow the premise rather than delete it. `measure_core` does put a *position*
on a wire; what it never does is put a handler's *answer* on one, which is the
conversion the section is about and the reason it lives in `driver`.

## Outcome

**Confirmed.** Both gaps closed and committed.

`[4a042110e0]`: `dispatch(handler, query, encoding)` derives the wire form on
the worker thread and returns `Dispatched::Decided(Answer)`, which carries
`outcome()` — byte-space, what `core` retains for §6's predicate — and
`wire()`, what goes to `writer:editor`. `Answer`'s fields are private and
there is no constructor taking both, so the wire half cannot be supplied
beside the byte half and disagree with it; the one public constructor,
`without_locations`, is the case with nothing to encode. The fixture puts a
four-byte character before the definition, so the three encodings produce
three different wire positions and a conversion that ignored the encoding it
was handed fails rather than looking plausible.

`[56ccb86901]`: the premise was false and the conclusion was not.
`measure_core` does put a *position* on a wire; it never puts an *answer* on
one, because it asks and reads the reply and the handler's `Location`s stay in
byte space into the record. So the conversion has one caller and lives with
it.

Two things worth carrying forward.

**`driver` may dev-depend on a grammar, and that unblocks handler doubles.**
`deadline.rs` had said for four campaigns that there is no handler double in
phase 1a because `LanguageHandler::grammar` returns a `tree_sitter::Language`.
That was never true of `[dev-dependencies]`: `seam.rs`'s grammar ban reads
`[dependencies]` only, and its own doc comment says why — "§9's graph is the
graph the shipped binary has, and a `[dev-dependencies]` grammar is not in
it". `shared` and `measure_core` already relied on that reading. Any campaign
blocked on "no handler double exists" should stop being blocked.

**`Location` carries a `line` and the conversion does not use it.** §8.4
argues the line from two consumers; only §6's predicate is one. The
read-free conversion the section describes needs a `WirePosition` constructor
that takes a line and a single line's text, and §8.3 deliberately has exactly
one constructor taking a whole `Rope`. That is a §8.3 change, not a §8.4 one,
and it is not a gap today — the conversion is correct, just not free.
