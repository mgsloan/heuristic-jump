## Hypothesis

§10 is unjudged-shaped rather than blocked: the audit's `found:` for each of
these names a *test* that does not exist, not a subsystem. The codec exists
(`measure_core/src/client.rs::read_frame`, with `CodecError`'s four
variants); the snapshot invariant's machinery exists (`TreeCache`, `dispatch`,
`ParseKind`, exercised by `driver/tests/snapshots.rs` at fixed inputs); and
the untagged unions are already covered by negative tests from campaign
0a979e94. What is missing in all three cases is the *randomised* or
*differential* half. Expect three commits and no production change beyond
whatever a property test proves wrong.

Risk to watch: `deps.md` §3 pins the `lsp-types` oracle *below* the release
that swapped `url::Url` for `fluent-uri`, because the whole point is
comparing against the same `Url` type we produce. A too-new pin makes the
differential compare nothing.

## Experiments

1. **Frame codec, extracted and fuzzed** (`[ddadbddae0]`). `Client::read_frame`
   became a free function over `&mut dyn BufRead`; proptest over split reads,
   oversized headers and bogus lengths. Found two real defects — an unbounded
   header line and a `Content-Length` believed before allocating — and made
   `Truncated.read` truthful. Gate green, committed `a99bdae`. Four mutations
   run, all caught.
2. **Snapshot version invariant** (`[c3f8c95546]`). Randomised edits and
   dispatches against a `TreeCache` fed exactly the edits its cached tree had
   not seen. Needed `shared::input_edit`, which did not exist. Gate green,
   committed `ced99c5`.
3. **Reverted, and the most useful result here:** pinning `input_edit`'s three
   `Point` fields through a tree. Four separate mutations to them pass a
   comparison against a from-scratch parse over kinds, byte ranges *and point
   ranges*. They are unobservable by construction — the read callback is
   byte-based and tree-sitter recomputes positions — so they are pinned against
   a reference implementation in `shared/tests/document.rs` instead.
4. **`lsp-types` differential** (`[cebab3e94d]`). Twenty-five hand-authored
   messages, both readings compared field by field, plus the manifest check
   `deps.md` §12 asks for. Gate green, committed `3317867`. Seven mutations
   run; six caught, and the survivor is a true negative (declaration order on a
   union disjoint by JSON kind, which is §8.5's own claim).
5. **Captured traffic** (`#85[3530047a3c]`, taken because it is the same file).
   `rust-analyzer` turned out to be installed. Six real server messages
   recorded; the differential passes over them unchanged. Gate green,
   committed `edf2c6b`.
6. **§8.4's carried row** (`[f2b9c0b7e5]`, taken because it is the same
   `proto.rs` and the same `WirePosition` design). Class A correction under
   `conformance-005`'s answered ruling, plus the check the correction exposed.
   Gate green, committed `fe50a83`. One mutation run, caught.

## Outcome

**`confirmed`.** `core.md#10-testing`'s three gaps are closed, and two
adjacent gaps in the same files went with them.

The hypothesis held exactly: §10 was unjudged-shaped rather than blocked, and
every `found:` in its audit entry was stale. What it did not predict is that
two of the three tests would need production code before they could assert
anything — the codec was unreachable and the edit-log conversion did not
exist — which is worth expecting next time. "The test does not exist" and "the
thing the test would call does not exist" look identical from the audit.

The one thing to carry: **the strong-looking oracle was the weak one.**
Comparing a reparsed tree against a from-scratch parse feels like it pins
everything and pins only what the parser reads. Mutating each field
individually is what found it, and nothing else would have.
