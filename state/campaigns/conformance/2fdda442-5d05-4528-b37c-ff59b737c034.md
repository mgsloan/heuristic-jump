## Hypothesis

`ServerId` has no producer because `ServerId(&'static str)` cannot be built
from a runtime command name without a table of the servers that exist, and no
such table has been written. `servers.toml` is that table already — it is the
canonical server matrix and is in no loop's write list — so the work is a
resolver in `shared` over a copy of that list, a test that the copy and the
canonical file agree, and both call sites (driver at startup, `measure_core` on
the replay path) going through it.

Expected to be structural rather than asserted: making `ServerProfile`'s field
private leaves `standalone()` and the two `proxying_*` constructors as the only
routes, so "the identity was discarded" stops being expressible.

## Outcome

Confirmed. `ServerId` now has producers on non-test paths — `Config::new` (the
driver's startup resolution, reached from `heuristic_jump::main`) and
`replay::Replay::one` (the measure path) — and `ServerProfile { id: … }` is no
longer constructible outside `shared`, so a call site holding a server name
cannot drop it without the type noticing.

The load-bearing test is `every_server_in_the_matrix_resolves_to_its_own_id`
(`crates/driver/tests/oracle.rs`), which reads the real `servers.toml` and
asserts both directions: every `[server.<name>]` header resolves by name, every
entry's real `command` array resolves by command line to that same id, and the
known set equals the header set. A server added to the matrix and not to
`ServerId::KNOWN` fails it, and vice versa.

Deliberately left, and it is somebody else's section: `measure_core`'s
`manifest::parse` cannot read the real `servers.toml` at all — it expects
`[[server]]` array-of-tables with `name`/`language` keys and single-line
values, where the file has `[server.<name>]` tables with `languages` and
multi-line `command` arrays. `resolve_server` therefore fails on the manifest's
first table header for every server, so `measure collect --server <anything>`
cannot work. That is `#where-the-corpus-lives` / `#two-modes` work.
