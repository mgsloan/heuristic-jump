## Hypothesis

The claim is unsatisfied for one reason and it is a small one: `Table` holds a
`latencies: Vec<u64>` and `render` prints `heuristic latency: p50 ... p99 ...`
in both formats, so the artifact the gate consumes carries a wall clock and two
runs differ. The existing determinism test
(`replay_is_deterministic_byte_for_byte`) tests the `--records` JSONL with
`heuristic_latency_us` masked, which is a different artifact and a weaker claim.

No spec change should be needed, and in particular the latency numbers are not
being dropped on the floor: §7's record is where the section already puts them —
"this single record type covers ... latency percentiles" — and it carries
`heuristic_latency_us` per query, which is strictly more than a global p50/p99
and is what `loops.md` §10's *per-stratum* percentiles actually need.
`loops.md` §9's "`measure replay` reports its own wall clock" is satisfiable on
the log stream, which is not the artifact the determinism claim is about.

So: remove the clock from the type, so no clock reading can reach `render` —
and make the rendered artifact a value a test can hold, since today it goes
straight to a `stdout` handle that cargo does not capture.
