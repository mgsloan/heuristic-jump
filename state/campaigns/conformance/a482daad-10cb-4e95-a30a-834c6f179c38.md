## Target

`core.md#both-sides-are-sets[6e601d5bd1]`, the whole of it.

Two claims, and they are one piece of work:

1. **Divergence is reported to the user on `mismatch` only.** A
   `match_contained` answer showed the user the correct location; telling them
   they were misled would be false, and would train them to ignore the reports
   that matter.
2. **The pending-query record holds the shim's ranked list, and its order is
   load-bearing** — `answered_by_shim` must preserve rank, not collapse to a
   set, or `top1` cannot be computed when the child eventually replies.

Picked because its section has exactly one gap against it, so closing it moves
the number, and because the classifier half is already complete
(`shared::agreement`): what is missing is the *caller* the section describes.

## Hypothesis

The audit's `found:` reads *"driver exposes only `Config` and `dispatch` —
there is no run loop, no pending-query record, and no construction site for
`ShowMessageParams` outside tests"*. The run loop is a false blocker of exactly
the shape the findings file names: remove it from the sentence and what is left
is ordinary code — a record type, a table keyed by `EditorRequestId`, and a
resolution step run when the child replies. None of it needs a transport to
exist, and none of it needs one to be tested.

Expected change: `#both-sides-are-sets` goes from one gap to clean, with both
claims mechanical rather than asserted —

* rank stays load-bearing by construction: the stored list is private, the
  setter takes the dispatch wrapper's `Answer` rather than a caller-supplied
  vector, and the only readout is the classification itself;
* "mismatch only" is structural: the report type has one private constructor,
  fed from `Agreement::severity()`, which is `None` on both match arms.

## Experiments

Two expectations inside it were wrong and were corrected rather than worked
around: the two fixture files share `src/`, so a cross-file mismatch classifies

report-content test ranked the child's own location second, which makes the
query a `match_contained` and therefore has no report at all. The second needed
a third fixture file, so that "the report names the top-ranked location" has
two wrong locations to choose between.

## Outcome

**Confirmed.** `core.md#both-sides-are-sets`'s two claims are now backed by
code and by six tests in `crates/driver/tests/pending.rs`.

What landed: `PendingQuery` as `shim.md` §7's `State` prints it (`editor_id`,
`uri`, `position`, `arrived`, `answered_by_shim`), `PendingQueries` as the
table `core` holds them in keyed by `EditorRequestId`, and `Resolution` /
`Divergence` as the step 4 comparison. The mismatch-only rule is enforced by
`Divergence::of` returning `Option` from `Agreement::severity()` rather than by
a convention anybody has to follow, and rank is preserved because
`answered_by_shim` takes an `&Answer` and the only readout builds
`DefinitionSite`s in stored order.

Both claims were mutation-checked before committing: sorting the stored list
turns `report_names_the_jump_it_refers_to` red, and reporting on
`Agreement::MatchContained` turns `a_report_is_produced_on_mismatch_only` red.

One deliberate omission, recorded rather than silent: `shim.md` §9 wants the
report to name *the symbol queried*, and the record cannot recover it — it
holds a `ByteOffset` into a document version that may be several edits gone by
the time the child replies. That is `shim.md`'s gap to close, by capturing the
token at answer time; it is out of scope for a phase whose audit reads
`core.md` only, and `Divergence`'s doc comment says so.
