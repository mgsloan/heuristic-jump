## Hypothesis

Both gaps are the same defect at different ends of one pipe: a number that
`replay_digest` already computes and nothing reads (`query_micros`), and a
dimension `measure replay --server` already takes and the row already drops
(the server).

Neither needs a corpus. `replay_digest` writes `strata[*].latency_p99_us`
today, which is exactly "per-query work" — so the guardrail's observed side
is a lookup in the history it already reads for `measure_binary_bytes`.
And `measure_core::table::Report` does not echo the server it was replayed
against, so the server must be supplied to `record` the way `--replay-seconds`
is: `measure_core` keeps the invocation out of the report on purpose.

The thing to be careful about is what the frontier does with several servers.
`#several-servers-…` forbids the obvious answer — merging or averaging two
servers' strata into one number is precisely what it says never to do — and
the agreement subset it *does* want cannot be computed from aggregate
per-server reports, only from the positions, which is `measure_core`'s. So
the expected shape is the `gate-select` shape from `68b83370`: build every
consumer, and refuse honestly, naming the producer that is missing.
