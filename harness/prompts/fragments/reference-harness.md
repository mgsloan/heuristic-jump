**The machinery you are building is the machinery you are running in.**
   That is an advantage and a trap. The advantage: when `loops.md` claims the
   supervisor reconciles desired state against observed, you can read
   `state/`, `harness/loop` and a real transcript and see whether it does. The
   trap: it is very easy to describe what the harness *does* rather than
   check what the document *claims*, and those come apart exactly where the
   gaps are.

   So read the claim first and the code second, in that order, and write down
   the claim before you go looking. A section that turns out to describe what
   is already there is a `clean` verdict, not a campaign.
